## 我改了什么（相对上游）

上游是「工艺品而非日用品」：设计精美（撕纸动效 + 252 套节气插画），但**为桌面大屏和打印设计，首屏要拉 14 MB，且存在若干真 bug**。

我做了两类工作：**① 性能与可用性重制 ② 移动端月视图从零重写**。

### 一、首屏瘦身：14 MB → 1.5 MB（↓89%）

| # | 上游实测问题 | 改法 | 效果 |
|---|---|---|---|
| 1 | 首屏要拉 **14 MB**，`calendar-templates.json` 独占 **12 MB**（252 套模板，其中仅 64 套带真实插画） | 拆成「常驻外壳 + 按需分片」，新增 `setAssetLoader` / `preloadTemplate` 两个 API | 首屏 **1.52 MB**（↓89%） |
| 2 | `FZXingKai-S04S.subset.woff2` 仓库里根本不存在，只能退到 2 MB 全量字体 | 用 fontTools **按运行时实际渲染字符**切子集（实测 607 字） | 2,030,480 → **155,616 B**（↓92%） |
| 3 | `remixicon-subset.woff2` 缺失，全量 174 KB 却**只用 2 个图标** | 只保留用到的 2 个字形 | 174,156 → **492 B**（↓99.7%） |
| 4 | `shengxiao.ttf`、`shengxiao1.ttf` 是 **130 B 的 Git LFS 指针**（文件其实是空的） | 从 LFS media 端点取回真身 | 生肖字形恢复显示 |
| 5 | `pdf-lib.min.js`、`fontkit.umd.min.js` 仓库中缺失（导出功能会直接崩） | 从 CDN 补齐 | 依赖完整 |
| 6 | `duizi.json` 与 `couplets.json` **MD5 完全相同**且无人引用 | 构建产物中排除 | 省 66 KB |
| 7 | 断网即废 | 加 `sw.js` + `manifest.json`，分片进缓存 | **服务器全挂仍可用** |
| 8 | `file://` 双击打开因 fetch 跨域失败而丢插画 | 内联 JSON，另出单文件版 | **双击即可用** |

> 关键方法：字体子集和资源分片一律按**「运行时真正会被渲染的字符 / 真正被引用的资源」**统计，而不是扫全库。
> 实测差异很大：按页面本体统计是 607 字（155 KB），扫全部 JSON 会得到 3296 字（855 KB）——后者纯属浪费。

### 二、移动端月视图（`src/`，从零写的）

上游只有一个「单日撕纸页」，手机上不好用。我参考国产日历 App 的紧凑排版，**从零重做了一个月视图**：

- **35 格月网格**：大号公历数字 + 小号农历，休/班用**右上角小圆角标**（不是文字标签）
- **节日与节气分色**：节庆红 / 节气绿；节日按优先级只显示一条（法定假期 > 农历大节 > 公历节日 > 节气）
- **点格弹出详情抽屉**：大号农历 + 干支、宜/忌、五行/冲煞/值神、财神/福神/喜神/阳贵、12 时辰宜忌、彭祖百忌
- **零滚动硬要求**：详情卡在 iPhone SE（375×667）到 430×932 五种竖屏尺寸下**纵向/横向溢出均为 0**（用春节当天最密内容回归）
- **年月选择器**：年份无限翻、5 格快选条、点「确定」才重渲染
- **入口清晰**：首页即月视图，☰ 进单日撕纸页，单日页底部悬浮胶囊返回

### 三、顺手修掉的上游真 bug

这几个不是审美问题，是**会输出错误数据**的缺陷：

| bug | 症状 | 修法 |
|---|---|---|
| `getTimeYi(参数)` 签名错误 | **12 时辰恒为「吉」**——假数据 | 改用 `Lunar.fromYmdHms()` 逐时辰构造 |
| 宜忌伪随机 | 用 `seed % 数组长度` 取宜忌，会出现「**宜嫁娶 忌嫁娶**」自相矛盾 | 改走真算法 |
| 法定假期名铺满区间 | 春节连写 9 天假名 | 改为仅当天显示 |

## 构建

**前置**：准备好上游仓库（提供 `index.html`、`lunar.js`、模板库、JSON 数据），并把本仓库的 `tools/`、`src/` 放进去。字体需自备合法授权版本。

```sh
python3 tools/split-templates.py     # 模板 JSON → 外壳 + 分片
python3 tools/build.py               # → dist/day.html（单日页）
python3 tools/build_month.py         # → dist/index.html（月视图，首页）
```

**部署**：把 `dist/` 整个目录挂到静态服务器即可。

```sh
cd dist && python3 -m http.server 8000
```

## 模板分片机制

`calendar-art.js` 打了补丁，新增两个 API：

- `CalendarArt.setAssetLoader(fn)` —— 注册图片加载器，`fn(assetId) → {data,width,height} | null`
- `CalendarArt.preloadTemplate(id)` —— 渲染前预热某模板用到的图片

外壳里每个 asset 只有 `{width, height}`、没有 `data`；渲染时 `ensureAsset()` 发现 `data` 为空就调加载器补齐，结果进内存缓存。**加载失败只降级、不报错**，日期数字照常显示。

## 踩坑记录（供参考）

1. **Cloudflare WAF 按文件名拦截**：索引文件原名 `shell.json`，CF 免费版有「shell 上传/命令注入」规则，**按文件名匹配**（改路径无效），过 CF 后 403。改名 `index-library.json` 解决。
   → 教训：静态资源命名避开 `shell` 等敏感词；**「路径改了仍 403」应立刻怀疑按文件名匹配的规则**。
2. **故障可能静默**：上述 403 只让插画缺失，页面照常渲染，**手机端完全看不出来**。上线后必须逐资源核对响应码，不能以「页面能打开」作为验收标准。
3. **`svg.term-art image` 的 locator 计数恒为 0**：插画在 shadow DOM 里，自动化测试不能拿计数当判据，得靠截图肉眼确认。
